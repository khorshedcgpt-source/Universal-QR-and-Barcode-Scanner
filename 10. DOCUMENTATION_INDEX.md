# 11. PDF417 AND BANGLADESH NID BOUNDARY

PDF417 has special importance in this project because the application is expected to handle use cases involving Bangladesh National ID cards.

However:

> **PDF417 does not automatically mean Bangladesh NID data.**

The generic scanner must first decode PDF417 as barcode data.

NID-specific processing must remain a separate layer.

Conceptual flow:

```text
PDF417
   ↓
Detection
   ↓
Decoding
   ↓
Raw Payload
   ↓
Encoding Verification
   ↓
Structure Detection
   ↓
NID-Specific Parser
   ↓
Validation
   ↓
Structured Result
```

The project must never invent or assume:

* NID payload structure
* Field names
* Field order
* Encoding
* XML structure
* Binary structure
* Encryption
* Compression
* Checksums
* Versioning

Any NID-specific implementation must be based on verified technical evidence.

# 30. FINAL PRINCIPLE

The Universal QR and Barcode Scanner project is governed by four primary engineering principles:

### Accuracy First

A scanner that works conveniently but produces unreliable results does not satisfy the project's core objective.

### Privacy First

Scanning should remain local by default, with unnecessary network processing and data collection avoided.

### Verification First

Library documentation, assumptions, or AI-generated claims are not substitutes for actual technical verification and testing.

### Controlled Development

The application must be developed incrementally through documented phases, measurable tests, and explicit architectural decisions.
