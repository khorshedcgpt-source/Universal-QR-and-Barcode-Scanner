# INITIAL PROJECT ANALYSIS — DO NOT IMPLEMENT YET

You are acting as a senior software architect and technical product analyst.

We are going to build an application named:

**Universal QR and Barcode Scanner**

Project description:

> An accuracy-first, privacy-focused QR & barcode scanner supporting multiple 1D and 2D formats, built for Android and Web.

## IMPORTANT INSTRUCTION

DO NOT build the application yet.

DO NOT generate the complete application code.

DO NOT start implementing features.

DO NOT create random files or change the project architecture.

The current objective is ONLY to analyze the project requirements and prepare a robust technical foundation before implementation begins.

## Primary Goals

The application should eventually provide:

* High-accuracy QR scanning
* High-accuracy 1D barcode scanning
* High-accuracy 2D barcode scanning
* Android support
* Web support
* Camera-based scanning
* Image/file-based scanning where technically appropriate
* Fast detection
* Reliable decoding
* Offline-first operation
* Privacy-focused processing
* Minimal permissions
* Clear scan results
* Scan history
* Copy/share/open actions
* Robust error handling
* Accessibility
* Maintainable architecture

## Accuracy-First Requirement

Accuracy is a primary engineering requirement.

The architecture must consider:

* False positives
* False negatives
* Poor lighting
* Motion blur
* Focus problems
* Small barcodes
* Large barcodes
* Rotated barcodes
* Perspective distortion
* Low contrast
* Damaged barcodes
* Multiple barcodes in one image
* Different camera qualities
* Different Android devices
* Different web browsers

Do not assume that every barcode format can be handled equally well by every scanning library.

## Privacy-First Requirement

The application should preferably process scanning locally on the user's device.

Do not introduce:

* unnecessary cloud processing
* unnecessary server APIs
* unnecessary analytics
* unnecessary tracking
* unnecessary user accounts
* unnecessary data collection

Any third-party SDK or library must be evaluated for:

* permissions
* network requirements
* telemetry
* licensing
* maintenance status
* platform compatibility
* privacy implications

## Platforms

The target platforms are:

1. Android
2. Web

The architecture should maximize code reuse while allowing platform-specific implementations where necessary.

Do not assume that one library must handle every platform if doing so reduces reliability or accuracy.
